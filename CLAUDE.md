# CLAUDE.md — Frontend Website Rules

## Always Do First
- **Invoke the `frontend-design` skill** before writing any frontend code, every session, no exceptions.

## Reference Images
- If a reference image is provided: match layout, spacing, typography, and color exactly. Swap in placeholder content (images via `https://placehold.co/`, generic copy). Do not improve or add to the design.
- If no reference image: design from scratch with high craft (see guardrails below).
- Screenshot your output, compare against reference, fix mismatches, re-screenshot. Do at least 2 comparison rounds. Stop only when no visible differences remain or user says so.

## Site Build
- The source is `src/index.html`. Root `index.html` and `<page>.html` files are generated — never edit them.
- After editing `src/index.html`, run `node build-pages.mjs` and commit the source and regenerated files together.

## SEO & Accessibility Requirements
Every change must keep all of these true. Fix any you break; don't leave them for later.

**Crawling & indexing**
- **sitemap.xml:** generated by `build-pages.mjs` from `pageMeta`, so every page is always listed. Never edit it by hand.
- **robots.txt:** allows all crawlers and includes `Sitemap: https://www.limitlessperiodontics.com/sitemap.xml`. Never block pages, CSS, JS or images.
- **No noindex:** remove any `noindex` in `<meta name="robots">` or an `X-Robots-Tag` header in `vercel.json`. Every public page must be indexable.
- **Canonical tags:** each page gets a self-referencing canonical (set by `build-pages.mjs`). Never point a page's canonical at another page.

**Page content**
- **Meta titles:** unique per page, 60 characters or fewer, set in `pageMeta`.
- **Meta descriptions:** unique per page, 70–160 characters, set in `pageMeta`.
- **One H1 per page:** mark each page's main heading with `class="page-h1"`; the build makes it the only `<h1>`. Style headings via `.page-h1`, never `h1`.
- **Heading order:** H1 → H2 → H3 with no skipped levels. Don't pick a heading level for its look; style it with a class instead.
- **Alt text:** every `<img>` has descriptive `alt` text; purely decorative images use `alt=""`.
- **Schema markup:** keep the `Dentist` JSON-LD in `src/index.html` accurate (address, phone, hours). `FAQPage` stays on home only, for questions visible on the page. The build adds `BreadcrumbList` (from the visible breadcrumb) and `BlogPosting` (blog posts) automatically. When a blog post's visible date matches its real publish date, add that date to `BLOG_DATES` in `build-pages.mjs`.
- **Internal links:** use real `<a href="/<page>" data-page="<page>">` links, never `<button onclick>` for navigation. Every page must be linked from at least one other page; link related service pages and blog posts to each other.
- **Broken links:** no internal 404s, broken anchors or missing images/PDFs. Fix or remove any broken link.

**Performance & layout**
- **Compress images:** put web images in `images/` as WebP (or AVIF), resized to 2× their largest display width; aim for under 200 KB. Keep originals out of `src=`. Every `<img>` needs `width`/`height` attributes from the file's real size, plus `loading="lazy"`, except images visible on load. The build makes each sub-page's first image eager; if a different image is the visible one, mark it `fetchpriority="high"` in the source.
- **Core Web Vitals:** target LCP < 2.5 s, INP < 200 ms, CLS < 0.1. Don't load render-blocking third-party scripts, and reserve space for images and embeds so nothing shifts.
- **Mobile layout:** check at 390px width: no horizontal scrolling, body copy at least 16px (section labels, captions, dates and footer small print may be smaller), and tap targets at least 44×44px. For small links and buttons, add the selector to the transparent `::after` hit-area rule rather than changing how they look.

**Accessibility & privacy**
- **Color contrast (including color-blind users):** meet WCAG AA, which is 4.5:1 for normal text and 3:1 for large text and UI controls. Never use color alone to convey meaning; pair it with text, an icon or an underline.
- **Cookie consent:** the banner (`#cookie-banner`, with equal-weight Accept and Reject buttons, stored in `localStorage` as `cookie-consent`) must stay on every page, and every footer keeps its **Cookie settings** link. Anything that sets cookies (today only the Google Maps embed) must use `data-consent-src` instead of `src`, so it loads only after Accept. If you add analytics or another embed, gate it the same way and update the banner text and Privacy Policy.

## LocalSpider Check (required before every commit)
Run every change through LocalSpider (`~/localspider`) and only commit when the site is SEO-clean:
1. Start LocalSpider: `cd ~/localspider && ./run.sh` → http://127.0.0.1:8765 (skip if already running).
2. Make sure `node serve.mjs` is running on http://localhost:3000.
3. Build with local canonicals: `SITE_URL=http://localhost:3000 node build-pages.mjs`. Without this, the crawler treats every page as canonicalised elsewhere and skips its duplicate checks.
4. Crawl `http://localhost:3000/` (tick the permission box). Require **zero errors and zero warnings**, and fix every notice unless there's a stated reason to keep it.
5. Rebuild for production with `node build-pages.mjs` (no `SITE_URL`), then commit.
6. After a deploy, crawl `https://www.limitlessperiodontics.com/` to confirm it's still clean.

LocalSpider doesn't check image weight, Core Web Vitals, color contrast or cookie consent. Check those separately: Lighthouse in Chrome DevTools covers performance and contrast, and a manual look at 390px width covers the mobile layout.

## Brand Assets
- Always check the `brand_assets/` folder before designing. It may contain logos, color guides, style guides, or images.
- If assets exist there, use them. Do not use placeholders where real assets are available.
- If a logo is present, use it. If a color palette is defined, use those exact values — do not invent brand colors.

## Anti-Generic Guardrails
- **Colors:** Never use default Tailwind palette (indigo-500, blue-600, etc.). Pick a custom brand color and derive from it.
- **Shadows:** Never use flat `shadow-md`. Use layered, color-tinted shadows with low opacity.
- **Typography:** Never use the same font for headings and body. Pair a display/serif with a clean sans. Apply tight tracking (`-0.03em`) on large headings, generous line-height (`1.7`) on body.
- **Gradients:** Layer multiple radial gradients. Add grain/texture via SVG noise filter for depth.
- **Animations:** Only animate `transform` and `opacity`. Never `transition-all`. Use spring-style easing.
- **Interactive states:** Every clickable element needs hover, focus-visible, and active states. No exceptions.
- **Images:** Add a gradient overlay (`bg-gradient-to-t from-black/60`) and a color treatment layer with `mix-blend-multiply`.
- **Spacing:** Use intentional, consistent spacing tokens — not random Tailwind steps.
- **Depth:** Surfaces should have a layering system (base → elevated → floating), not all sit at the same z-plane.

## Hard Rules
- Do not add sections, features, or content not in the reference
- Do not "improve" a reference design — match it
- Do not stop after one screenshot pass
- Do not use `transition-all`
- Do not use default Tailwind blue/indigo as primary color
